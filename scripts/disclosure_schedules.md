# 결산실적 공시예고 일정 등록

월~금 22:00 KST에 별도 스케줄러가 `disclosure_schedule_extraction.py`를 실행합니다.
토요일과 일요일에는 실행하지 않습니다. 공휴일도 월~금이면 실행합니다.
기업공시 백업과 정리는 기존대로 매일 00:00 KST에 실행하며, 일정 등록은 호출하지 않습니다.
자동 실행은 원본 `disclosure_news_list_filtered.json`만 읽고, 공시의 `timestamp`를
KST로 변환하여 실행일의 오늘 날짜인 항목만 처리합니다. 전날 공시와 날짜 불명 항목은 제외합니다.
그중 `결산실적공시예고` 제목을 추립니다.

날짜 지정 수동 실행은 `python disclosure_back_up_scheduler.py YYMMDD`를 사용합니다.
예: `python disclosure_back_up_scheduler.py 261027`은
`news_back_up/disclosure_news_list_filtered_backup_261027.json`만 읽습니다.
해당 백업이 없으면 오류로 종료하며 다른 파일로 대체하지 않습니다.
날짜 인자를 생략한 수동 실행은 자동 실행과 같은 원본/오늘 날짜 조건을 사용합니다.
DART 본문 3번 항목의 공시예정일을 일정 날짜로 사용하고, 4번 항목에서 공백과 줄바꿈을
제외한 `잠정` 키워드(잠정치 포함) 유무에 따라 `회사명 (잠정)실적발표` 또는
`회사명 실적발표`를 생성합니다. 코스닥의 `기타 투자판단에 참고할 사항`도 지원합니다.
본문/날짜 파싱 실패 시 등록하지 않으며 배치 실패로 기록합니다.

기존 서비스 계정 설정을 이용해 Firestore 실제 일정 컬렉션 `events`에 바로 저장합니다.
기존 `temp_events` 문서는 자동 이동하거나 삭제하지 않습니다.
`category`는 `한국실적`, `eventName`과 `title`은 생성한 일정명, `detail`은 2번 항목에서 추출한 `결산대상기간: YYYY-MM-DD ~ YYYY-MM-DD`입니다.
기간 항목이 없으면 본문을 비워두고, 항목은 있으나 날짜가 잘못됐으면 등록 실패로 처리합니다.
제목+일자 기반 문서 ID와 create를 사용해 기존 일정을 덮어쓰지 않습니다.
이미 처리한 공시 URL은 다음 배치에서 본문 수집을 건너뜁니다.
정정 공시는 별도 접수번호로 처리하며 기존 일정 삭제/변경은 자동 수행하지 않습니다.

`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`로 새로 등록한 일정의 발표일·제목을 한 메시지로 모아서
보냅니다. 링크는 포함하지 않으며 Telegram의 4096자 제한을 넘는 경우에만 나눠 보냅니다. 등록일은 실행일(KST)이며 22시까지 수집된 당일 공시도 처리합니다.
전송 성공한 일정은 완료 표시하고, 미전송 일정은 다음 실행에 재시도합니다.
텔레그램 전송 직후 DB 완료 표시가 실패하면 재전송이 발생할 수 있습니다.
과거 날짜의 등록 실패 건은 해당 날짜를 지정하여 백업으로 수동 재처리합니다.
파일은 공시 수집과 같은 잠금으로 읽고, 네트워크 작업은 잠금 해제 후 별도 스레드에서 수행합니다.
실행 결과는 `disclosure_earnings_schedules` 배치로 따로 기록합니다.

서버에 변경 코드를 반영하고 앱을 재시작하면 다음 월~금 22:00 배치부터 적용됩니다.
Firebase 서비스 계정과 텔레그램 환경 변수는 기존 서버 설정을 사용합니다.

검증: `python -m unittest discover -s tests -p 'test_disclosure*.py'`
